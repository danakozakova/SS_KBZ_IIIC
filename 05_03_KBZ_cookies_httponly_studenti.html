HttpOnly: kto smie prečítať cookie?

Dnešok má dve časti. Najprv (Časť 1) spustíš malý server v Pythone (Flask) a zistíš, kto smie cookie prečítať — a čo spraví HttpOnly. Potom (Časť 2) si na vlastnej stránke ukážeš, prečo na tom záleží: spravíš a opravíš bezpečnostnú chybu XSS.

Z minula · Nadväzuje

Minule si si vyrobil vlastnú cookie JavaScriptom a videl, že ju cez document.cookie vieš prečítať aj prepísať. Dnes skúmame cookie, ktorú nastaví server — a atribút HttpOnly, ktorý JavaScriptu zoberie prístup k jej hodnote.

🎯
Cieľ hodiny: pochopiť, čo presne HttpOnly zabráni a čo nie. Nejde o naučenie Flasku — server aj stránku máš hotové, dopĺňaš jediný riadok a hlavne pozoruješ rozdiel.
⚠️
Pracujeme len s fiktívnym tokenom FIKTIVNY_TOKEN_123 a lokálnym serverom na tvojom počítači (127.0.0.1). Nikdy sem nedávaj skutočné prihlasovacie tokeny ani heslá. Toto je učebný pokus, nie prihlasovací systém.

Najprv: kto čo robí

Server aj prehliadač bežia na tom istom počítači, ale sú to dva odlišné procesy s dvoma odlišnými úlohami.

Prehliadač

HTML + JavaScript

zobrazuje stránku, vykonáva JavaScript, uchováva cookies

Server

Python + Flask

prijíma HTTP požiadavky, vytvára odpovede, môže nastaviť cookie

HttpOnly je atribút, ktorý cookie pridá server v hlavičke Set-Cookie. Cookie s HttpOnly JavaScript cez document.cookie neprečíta — prehliadač ju však stále môže poslať serveru a používateľ ju vidí v DevTools.

Časť 1 · HttpOnly — kto smie cookie prečítať

1

Priprav si priečinok a súbor app.py

prečo — server musí existovať ako súbor, ktorý vieme spustiť

  1. Otvor priečinok 05_03_httponly_demo (dostal si ho od učiteľky) vo VS Code: File → Open Folder… → vyber 05_03_httponly_demo.
  2. Je v ňom súbor app.py — s ním budeš pracovať.

Kód dnes netreba rozoberať po riadkoch. Všimni si len dve veci: hore premennú HTTP_ONLY = False a v <script> riadok s /* DOPLŇ */ — ten doplníš v kroku 3. Celá stránka je uložená ako text v premennej PAGE — server ju len pošle, prehliadač ju spustí; preto je JavaScript vnútri úvodzoviek.

app.py 
from flask import Flask, make_response, request

app = Flask(__name__)

# Experimentálny prepínač. Najprv cookie JavaScriptu sprístupníme (False).
# V pokuse B ho zmeníš na True.
HTTP_ONLY = False

PAGE = """
<!doctype html>
<html lang="sk">
<head>
  <meta charset="utf-8">
  <title>Pokus s HttpOnly</title>
</head>
<body>
  <h1>Kto môže prečítať cookie?</h1>

  <p>
    Cookie obsahuje iba fiktívny token.
    Toto nie je skutočné prihlásenie.
  </p>

  <button id="read">Prečítať cookies JavaScriptom</button>
  <pre id="result"></pre>

  <p>
    <a href="/kontrola">Overiť, či cookie dostane server</a>
  </p>

  <script>
    document.querySelector("#read").addEventListener("click", () => {
      // ÚLOHA A — doplň pravú stranu:
      // majú to byť cookies, ktoré vidí JavaScript aktuálnej stránky.
      const cookies = /* DOPLŇ */;

      document.querySelector("#result").textContent =
        cookies || "JavaScript nevidí žiadne dostupné cookies.";
    });
  </script>
</body>
</html>
"""


@app.route("/")
def index():
    response = make_response(PAGE)

    response.set_cookie(
        "demo_token",
        "FIKTIVNY_TOKEN_123",
        max_age=600,
        path="/",
        httponly=HTTP_ONLY,
        samesite="Lax",
    )

    return response


@app.route("/kontrola")
def kontrola():
    token = request.cookies.get("demo_token")

    if token == "FIKTIVNY_TOKEN_123":
        message = "Server dostal očakávanú fiktívnu cookie."
    else:
        message = "Server nedostal očakávanú fiktívnu cookie."

    return (
        f"<h1>{message}</h1>"
        '<p><a href="/">Späť na pokus</a></p>'
    )


if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000, debug=False)
2

Nainštaluj Flask

prečo — Flask nie je súčasť štandardného Pythonu, treba ho doinštalovať

  1. Otvor terminál: Terminal → New Terminal (pracuje v otvorenom priečinku).
  2. Over Python: 
    python --version
    Ak ti funguje py alebo python3, používaj rovnaký príkaz aj ďalej.
  3. Nainštaluj Flask: 
    python -m pip install flask
⚠️
Zápis python -m pip inštaluje balík presne do toho Pythonu, ktorý spúšťaš. Ak neskôr vyskočí ModuleNotFoundError: No module named 'flask', pozri časť Ak sa niečo pokazí.
3

Doplň jeden riadok úloha A

prečo — toto je presne to miesto, kde JavaScript číta cookies stránky

V app.py nájdi v <script> riadok s medzerou a doplň pravú stranu tak, aby to boli cookies dostupné JavaScriptu aktuálnej stránky:

const cookies = document.cookie;

Ulož súbor Ctrl+S.

5

Pokus A — bez HttpOnly (HTTP_ONLY = False)

prečo — najprv uvidíš stav, keď JavaScript cookie prečítať smie

  1. Klikni Prečítať cookies JavaScriptom. Vo výpise nájdi demo_token=FIKTIVNY_TOKEN_123.
  2. Otvor F12 → Application → Cookies → položka pre 127.0.0.1 → nájdi demo_token. Stĺpec HttpOnly nie je označený.
  3. Klikni odkaz Overiť, či cookie dostane server. Očakávaný výsledok: „Server dostal očakávanú fiktívnu cookie."
💡
Cookie vytvoril server, ale nemá HttpOnly — preto ju JavaScript prečíta. Samotné serverové nastavenie cookie teda nezaručuje, že je pred JavaScriptom skrytá.

Vo výpise sa môžu objaviť aj iné cookies pre 127.0.0.1 (cookies sa nedelia podľa portu). Sleduj konkrétne demo_token, nie celý výpis.

6

Pokus B — zapni HttpOnly

prečo — teraz serveru povieš, aby cookie pred JavaScriptom skryl

  1. V app.py zmeň HTTP_ONLY = False na HTTP_ONLY = True a ulož Ctrl+S.
  2. Klikni do terminálu, kde beží Flask, a zastav server Ctrl+C.
  3. Spusti ho znova: python app.py.
  4. V prehliadači znova načítaj http://127.0.0.1:5000.
  5. Opäť klikni Prečítať cookies JavaScriptom.
🔁
Prečo reštart a nové načítanie? Server má debug=False, takže sa po uložení sám nereštartuje — bežiaci proces používa staré nastavenie. A reštart servera sám cookie v prehliadači nezmení: až nová odpoveď na / ju nastaví znova, teraz s HttpOnly.
💡
Očakávanie: demo_token sa vo výpise JavaScriptu už nezobrazí. Ostatné cookies bez HttpOnly sa zobrazovať môžu.
7

Over, že cookie nezmizla

prečo — HttpOnly nie je zákaz cookie, len obmedzenie prístupu cez JavaScript

  1. F12 → Application → Cookies → demo_token tam stále je a jej hodnotu vidíš.
  2. Stĺpec HttpOnly je teraz označený.
  3. Klikni Overiť, či cookie dostane server. Výsledok je stále „Server dostal očakávanú fiktívnu cookie."

Časť 2 · XSS — ukradni token a potom to oprav

⚖️
Pravidlá vopred (dôležité): pracuješ len na vlastnej lokálnej stránke a s fiktívnym tokenom. Cieľ je pochopiť útok, aby si ho vedel ustrážiť. Skúšať toto na cudzích weboch alebo so skutočnými údajmi je protizákonné — nič sa nikam neposiela.
Prečo to robíme

V Časti 1 si videl, že bez HttpOnly JavaScript cookie prečíta. Teraz uvidíš, prečo je to nebezpečné: necháme na stránku vniknúť cudzí skript, ktorý token ukradne — a potom to dvoma spôsobmi opravíme.

10

Útok — ukradni token úloha G

prečo — uvidíš, že cudzí skript číta cookie presne ako tvoje tlačidlo v Časti 1

Do políčka odkaz vlož tento „útočníkov" kód a stlač Zobraziť:

<script>fetch('/zber?c=' + encodeURIComponent(document.cookie))</script>
  1. Pozri sa do terminálu vo VS Code, kde beží server.
  2. Uvidíš riadok: ‼️ [utocnik] prislo mi: demo_token=FIKTIVNY_TOKEN_123.
🩸
Čo sa stalo: tvoj vložený <script> sa spustil na stránke, prečítal cookie cez document.cookie a poslal ju na /zber („server útočníka"). V reálnom svete by šla na cudzí server a útočník by mal tvoje prihlásenie. Prehliadač nerozlišuje tvoj a cudzí skript — spustí každý, čo je na stránke.
11

Obrana A — escapovanie úloha H skutočná oprava

prečo — odstránime príčinu: vstup sa už nebude vkladať ako kód

  1. Hore v app.py pridaj import: 
    from markupsafe import escape
  2. Nájdi riadok s chybou a oprav ho: 
    telo = "<p>Posledný odkaz: " + str(escape(odkaz)) + "</p>"
  3. Ulož, reštartuj server (Ctrl+C, python app.py) a skús znova vložiť ten <script>.
✅
Teraz sa skript nespustí — na stránke uvidíš doslova napísané <script>…</script> ako text a v termináli už nič nepríde. escape() premení < > na &lt; &gt; → prehliadač to berie ako text, nie príkaz.
12

Obrana B — HttpOnly úloha I poistka

prečo — uvidíš, čo HttpOnly spraví, keď diera (zámerne) OSTANE

  1. Dočasne vráť chybný riadok späť (bez escape) — chceme vidieť útok, keď diera ostane.
  2. Hore zmeň HTTP_ONLY = False na True, ulož, reštartuj server, obnov /.
  3. Skús injekciu z úlohy G znova a pozri do terminálu.
🛡️
Skript sa stále spustí (dieru sme nechali), ale v termináli už token nie je — document.cookie ho pri HttpOnly nevráti, útok nemá čo ukradnúť. Pozor: iné cookies bez HttpOnly by stále unikli a skript môže páchať aj iné škody. Preto Obrana A je skutočná oprava, HttpOnly je len poistka.

Záver Časti 2: XSS vznikne, keď sa údaj od používateľa dostane do stránky ako kód. Hlavná obrana je escapovať výstup („ber to ako text, nie príkaz"). Čo si z toho odniesť

✅
HttpOnly je atribút cookie nastavený serverom. Cookie s HttpOnly JavaScript stránky neprečíta cez document.cookie. Prehliadač ju však stále automaticky posiela serveru a používateľ ju vidí v DevTools.
🛡️
Pointa: ak JavaScript prihlasovací identifikátor nepotrebuje čítať, zbytočne mu tento prístup nedávame. Keby cookie niesla platný identifikátor relácie a na stránku sa dostal útočníkov skript (napr. cez XSS), bez HttpOnly by ho prečítal rovnako ako naše tlačidlo.
🚫
Čo HttpOnly NEvyrieši: nešifruje hodnotu cookie · neschová ju pred používateľom DevTools · neoverí, že hodnota je pravdivá · nenahrádza HTTPS, Secure ani SameSite · nevyrieši celé XSS (škodlivý skript môže stále meniť stránku a posielať požiadavky).
Zamysli sa · úloha E

Minule bola cookie so zvoleným menom čitateľná JavaScriptom a nevadilo to. Prihlasovací identifikátor by sme pred ním spravidla chránili. Vysvetli jednou-dvoma vetami, prečo je v tom rozdiel.

Dva problémy, ktoré si nezamieňaj

A · dôveryhodnosť vstupu

Môžeme veriť tvrdeniu z prehliadača?

Napr. rola=administrator v cookie nestačí na prístup. O oprávneniach rozhoduje server na základe overených údajov. Skrytie tlačidla JavaScriptom nie je kontrola prístupu.

B · prístup skriptu k údaju

Má JavaScript vôbec vedieť prečítať token?

Práve toto rieši HttpOnly. Nie je to podpis, šifrovanie ani potvrdenie identity — iba obmedzenie priameho čítania hodnoty cez JavaScript.

Ďalšie úlohy a projekty

Rýchle na hodinu

  • V DevTools → Network obnov stránku /, vyber HTML dokument a v Response Headers nájdi Set-Cookie. Pri zapnutej ochrane skontroluj prítomnosť HttpOnly.
  • Klikni na /kontrola a v Request Headers nájdi hlavičku Cookie — demo_token tam je aj pri zapnutom HttpOnly.

Technické náročnejšie

  • Pridaj v serveri druhú cookie bez HttpOnly (iný názov) a over, ktorá z dvojice sa po zapnutí HttpOnly objaví vo výpise JavaScriptu a ktorá nie.
  • Zmeň port na 5001 v app.run(...) a over, že demo funguje aj na http://127.0.0.1:5001.

Diskusia skupinové

  • Kde v reálnej aplikácii dáva zmysel HttpOnly (napr. relačná cookie) a kde naopak potrebujeme cookie, ktorú JavaScript má čítať (napr. zvolený jazyk, stav súhlasu)?

Na známku na známku

  • Krátky zápis (3–5 viet): čo HttpOnly robí, čo nerobí, a prečo server cookie stále dostane, aj keď ju JavaScript neprečíta.
  • Druhý zápis (3–5 viet): čo je XSS, ako sa cez ňu dá ukradnúť token, a čím sa líšia dve obrany (escapovanie vs. HttpOnly) — ktorá je skutočná oprava a prečo.

Ak sa niečo pokazí

  • ModuleNotFoundError: No module named 'flask': Flask nie je v tom Pythone, ktorým spúšťaš. V tom istom termináli skús python -m pip show flask, potom python -m pip install flask a znova python app.py.
  • Python sa nenašiel: použi školský spôsob — py alebo python3. Nemeň príkaz medzi inštaláciou a spustením.
  • Port 5000 je obsadený: zastav starý server Ctrl+C, alebo zmeň port na 5001 v app.run a otvor http://127.0.0.1:5001.
  • Cookie zostáva vo výpise aj po zmene na True: je súbor uložený? reštartoval si správny server? obnovil si cestu / (tá cookie nastavuje)? sleduješ naozaj demo_token?
  • Server nedostal očakávanú cookie: najprv otvor /, až potom /kontrola — samotná /kontrola cookie nevytvára.
